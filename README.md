# CineMate

CineMate — рекомендательный сервис фильмов: пользователь ставит лайки и дизлайки, а
user-based коллаборативная фильтрация подбирает, что посмотреть дальше. Когда данных мало,
используется запасной вариант — популярные и хорошо оценённые фильмы. Сначала отлаживается
алгоритм на MovieLens (метрики precision/recall), потом строится сайт. Подробнее — в
[docs/VISION.md](docs/VISION.md).

## Как запустить

Два способа: всё в Docker (база PostgreSQL, ничего, кроме Docker, ставить не нужно) или в
консоли (Python и Node.js на своей машине, база по умолчанию — файл SQLite `cinemate.db`).
Команды даны для Windows PowerShell; отличия для Linux/macOS — в комментариях.

### В Docker

Первый запуск (`.env`, миграции, импорт данных) описан в разделе [Docker](#docker).

**Повторный запуск, например после перезагрузки компьютера.** Контейнеры сами не стартуют:

1. Запустите Docker Desktop и дождитесь, пока он загрузится.
2. Из папки проекта:

   ```
   docker compose up -d
   ```

3. Откройте <http://localhost:3000>. Состояние сервисов — `docker compose ps` (у `db` и `api`
   должно быть `healthy`), логи API — `docker compose logs -f api`.

**После обновления кода** (`git pull`):

```
docker compose build
docker compose --profile tools build app
docker compose run --rm app migrate
docker compose up -d
```

`docker compose build` не собирает сервис `app` (профиль `tools`), поэтому нужна вторая команда:
без неё разовые команды `docker compose run --rm app ...` работают на старом коде (например,
`migrate` не знает новых ревизий).

**После импорта данных** (`import-movielens`, `import-ratings-csv`) перезапустите API — он
держит матрицу оценок в памяти: `docker compose restart api`.

**Прерванный импорт** (перезагрузка, Ctrl+C) — запустите ту же команду ещё раз, повторный запуск
ничего не дублирует. `import-ratings-csv` сохраняет сопоставленные фильмы и ответы TMDB по ходу
работы и продолжает с места остановки; пользователи и оценки записываются в самом конце.

**Остановка:** `docker compose down` (данные базы остаются в томе `pgdata`).

### В консоли

Нужны Python 3.12+ и Node.js. API и фронтенд работают в двух разных терминалах. Если сервисы
запущены в Docker, сначала остановите их (`docker compose stop frontend api`): фронтенд из Docker
занимает порт 3000.

**Один раз — установка и данные:**

```
python -m venv .venv
.venv\Scripts\activate                      # Linux/macOS: source .venv/bin/activate
pip install -e ".[dev,postgres]"            # extra postgres нужен только для PostgreSQL
cd frontend
npm install
copy .env.example .env.local                # Linux/macOS: cp .env.example .env.local
cd ..
$env:TMDB_API_KEY = "ваш ключ"              # Linux/macOS: export TMDB_API_KEY=...
cinemate migrate
cinemate import-movielens --data-dir data
cinemate import-ratings-csv --file data/ratings.csv   # свой набор оценок (пул ru), если есть
cinemate enrich-movies                      # постеры и описания из TMDB
```

CLI не читает `.env`: переменные окружения (`TMDB_API_KEY`, `DATABASE_URL` и другие из
раздела [Переменные окружения](#переменные-окружения)) задавайте в терминале — в каждом новом
окне заново.

**Каждый запуск.** Терминал 1 — API:

```
.venv\Scripts\activate                      # Linux/macOS: source .venv/bin/activate
$env:TMDB_API_KEY = "ваш ключ"              # Linux/macOS: export TMDB_API_KEY=...
cinemate serve --host 127.0.0.1 --port 8000
```

Терминал 2 — фронтенд:

```
cd frontend
npm run dev
```

Откройте <http://localhost:3000>. Остановка — Ctrl+C в обоих терминалах.

**Консоль и база из Docker.** По умолчанию консольные команды работают с файлом `cinemate.db` —
это отдельная база, данных из Docker в ней нет. Чтобы работать с базой PostgreSQL из Docker:

1. Создайте рядом с `docker-compose.yml` файл `docker-compose.override.yml` (он в `.gitignore`,
   `docker compose` подхватывает его сам):

   ```yaml
   services:
     db:
       ports:
         - "127.0.0.1:5432:5432"
   ```

2. Запустите базу: `docker compose up -d db`.
3. В терминале перед командами `cinemate` задайте URL (пароль — `POSTGRES_PASSWORD` из `.env`):

   ```
   $env:DATABASE_URL = "postgresql+psycopg://cinemate:ПАРОЛЬ@localhost:5432/cinemate"
   ```

## Команды

```
cinemate --version
```

### `cinemate evaluate`

Скачивает MovieLens (`ml-latest-small`) при первом запуске и печатает таблицу метрик
«коллаборативная фильтрация против популярного».

```
cinemate evaluate --k 40 --lambda 5 --min-overlap 5 --top-n 10 --seed 0
```

Аргументы: `--data-dir` (по умолчанию `data`), `--k`, `--lambda`, `--min-overlap`,
`--top-n`, `--seed`.

Кроме precision, recall, hit rate, покрытия и популярности таблица (и `cinemate tune`) содержит
метрики по дизлайкам из тестовой части: `dislike@N` — средняя доля рекомендаций из топ-N,
которые пользователь дизлайкнул (**лучше меньше**), и `like_share_judged` — доля лайков среди
рекомендованных фильмов, которые пользователь оценил в тесте (**лучше больше**). Её среднее
берётся только по пользователям, у которых в топ-N есть хотя бы один оценённый в тесте фильм;
число таких пользователей печатается рядом как `(n=…)`. При нескольких сидах показываются
среднее и разброс (`±`); `n` — среднее по сидам.

### `cinemate tune`

Перебирает значения параметров и выводит таблицу, отсортированную по precision. Параметры
принимают списки через запятую.

```
cinemate tune --k 20,40,80 --lambda 2,5,10 --min-overlap 1,2,3
```

Аргументы: `--data-dir`, `--k`, `--lambda`, `--min-overlap`, `--top-n`, `--seed`.

### `cinemate import-movielens`

Идемпотентно импортирует фильмы, пользователей и оценки MovieLens в базу данных. Поле
`Movie.popularity_score` пересчитывается как число лайков (`+1`) фильма; без лайков — `0.0`.
Названия приводятся к читаемому виду («Blair Witch Project, The» → «The Blair Witch Project»,
альтернативное название из скобок уходит в пустое `original_title`); повторный запуск
обновляет названия уже импортированных фильмов.

```
cinemate import-movielens --database-url sqlite:///cinemate.db --data-dir data
```

### Набор ml-32m

`evaluate`, `tune` и `import-movielens` принимают `--dataset {ml-latest-small,ml-32m}` (по умолчанию
`ml-latest-small`). `ml-32m` — около 32 млн оценок, 200 тысяч пользователей, 87 тысяч фильмов:
архив ≈ 240 МБ, после распаковки в `data/ml-32m` ≈ 900 МБ (`data/` в `.gitignore`). Если GroupLens
публикует рядом с архивом файл `.md5`, скачанный архив проверяется по нему.

Отбор пользователей общий для трёх команд: `--min-user-ratings N` (по умолчанию 0) и
`--max-users N` (случайная выборка среди подходящих, детерминированная по `--seed`). `ratings.csv`
читается в два прохода: первый считает оценки по пользователям, второй отдаёт оценки выбранных;
импорт не держит весь файл в памяти. `evaluate` и `tune` загружают в память оценки выбранных
пользователей, поэтому для `ml-32m` задавайте `--max-users` (без него это ≈ 32 млн оценок). Повторный `import-movielens` пропускает пользователей,
которые уже есть в базе, вместе с их оценками; оценки пишутся пачками по 10 000 строк, прогресс
печатается раз в 1 млн прочитанных оценок.

```
cinemate import-movielens --dataset ml-32m --min-user-ratings 50 --max-users 30000
cinemate evaluate --dataset ml-32m --min-user-ratings 50 --max-users 5000
```

Скорость импорта не замерена (пользователи создаются по одному, оценки — пачками); по порядку величины (оценка, а не измерение)
на SQLite это единицы минут на каждый миллион записанных оценок, а чтение двух проходов по файлу —
около минуты. Рекомендуемый отбор `--min-user-ratings 50 --max-users 30000`.

Лицензия `ml-32m` та же, что у `ml-latest-small`: только некоммерческое использование, атрибуция
GroupLens (F. Maxwell Harper and Joseph A. Konstan, *The MovieLens Datasets: History and Context*,
ACM TiiS 5(4), 2015).

### `cinemate enrich-movies`

Обновляет данные фильмов и сериалов с парой TMDB (`tmdb_type`, `tmdb_id`): названия
(оригинальное, английское и русское `title_ru`), год, описание (русское, если есть), постер и
длительность. Запрос идёт на `/movie/{id}` или `/tv/{id}` по `tmdb_type`. Пустое значение TMDB не
стирает сохранённое, жанры заменяются жанрами TMDB (см. «Признаки фильмов»), IMDb ID
привязывается к записи. Требуется переменная
окружения `TMDB_API_KEY`.

```
export TMDB_API_KEY=...
cinemate enrich-movies --database-url sqlite:///cinemate.db --limit 100
```

Зачем обновлять регулярно:

- у новинок постер, русское название и описание появляются на TMDB позже самой записи;
- [условия использования API TMDB](https://www.themoviedb.org/api-terms-of-use) (§1.C) не
  разрешают хранить полученные данные дольше 6 месяцев.

Время получения хранится в `movies.tmdb_fetched_at` (его проставляют и `enrich-movies`, и
добавление фильма из живого поиска). Команда без флагов обновляет записи, у которых отметки нет
(сначала они) или она старше `--stale-days` (по умолчанию 30, допустимо 1–180), самые старые
первыми. Записи, которых TMDB не знает (404), не меняются и считаются «не найдено»; записи без
пары TMDB пропускаются. Прогресс сохраняется пачками по 100 записей и при ошибке.

Опции: `--limit N` ограничивает число запрошенных записей; `--refresh-titles` запрашивает только
записи без `title_ru`, независимо от возраста данных; `--missing-features` дозаполняет признаки
фильмов (см. ниже); `--workers N` (1–16, по умолчанию 8) и `--rps X` (до 35, по умолчанию 20)
задают число параллельных запросов к TMDB и общий предел запросов в секунду (подробнее в разделе
«Скорость загрузки из TMDB»).

Итог: `movies enriched: N, not found: M, skipped (no TMDB pair): K`.

Рекомендация: запускать раз в неделю. На Windows — через Планировщик заданий:

```
docker compose run --rm app enrich-movies
```

Первый запуск после миграции обновит все записи (у существующих `tmdb_fetched_at` пуст); для
10 тысяч фильмов при лимите клиента это порядка 10 минут. Дальше за неделю устаревает примерно
четверть каталога.

## Оценка на внешнем наборе оценок

`evaluate` и `tune` умеют читать оценки не только из MovieLens, но и из своего `ratings.csv` (шкала 1–10), без БД и без сети. Файл — с заголовком, порядок колонок произвольный, лишние колонки игнорируются:

```
user_id,kp_id,tmdb_type,tmdb_id,imdb_id,title_ru,title_original,type,year,genres,user_rating
18481579,9353768,,,,Холодец-молодец,,MiniSeries,2025,"комедия, драма",9
```

Обязательны `user_id` и `user_rating` (целое 1–10), а в каждой строке — хотя бы один из `kp_id` (ID Кинопоиска; старое имя колонки `movie_id` принимается как синоним с предупреждением), `tmdb_id` (вместе с `tmdb_type` — `movie` или `tv`) и `imdb_id` (`tt` и цифры); если указаны TMDB/IMDb, они приоритетнее. Несогласованные `tmdb_type`/`tmdb_id` и неверный `imdb_id` — ошибка с номером строки. Остальные колонки (в том числе `kp_rating`) необязательны, `genres` — список через запятую. Ключ фильма в `evaluate`/`tune`: пара TMDB, иначе `imdb_id`, иначе `kp_id`. При повторе пары (пользователь, фильм) побеждает последняя строка.

```
cinemate evaluate --source csv --ratings-csv data/ratings.csv
cinemate tune --source csv --ratings-csv data/ratings.csv --types Film,TvSeries
```

- `--types Film,TvSeries,…` — оставить только фильмы указанных типов (без учёта регистра; строки без `type` отбрасываются); по умолчанию все.
- `--rel-threshold` (по умолчанию `0.5`, строго больше 0) — оценка, превышающая личное среднее пользователя на этот порог и больше, это лайк (`+1`), ниже среднего на порог и больше — дизлайк (`-1`), остальные отбрасываются. Пользователи с менее чем 20 оценками отбрасываются целиком.
- Допущение: среднее считается один раз на пользователя по всем оценкам файла, поэтому тестовые оценки входят в него и дают небольшое смещение.

Перед таблицей печатается сводка по набору данных (пользователи, фильмы, оценки, плотность, доли `+1`/`-1`/отброшенных) — для обоих источников, чтобы сравнение с MovieLens было честным.

## Внешний набор оценок

Оценки из `ratings.csv` (формат — в разделе выше) можно загрузить в ту же БД, что и MovieLens: фильмы, пользователей и оценки. Порядок команд:

```
cinemate migrate
cinemate import-movielens
cinemate import-ratings-csv --file data/ratings.csv [--types Film,TvSeries] [--rel-threshold 0.5]
```

В Docker: `docker compose run --rm app import-ratings-csv --file data/ratings.csv`.

- Файл кладите в `data/` — каталог не коммитится.
- Каждый уникальный фильм файла сопоставляется с каталогом в таком порядке:
  1. пара `tmdb_type`/`tmdb_id` → фильм каталога или импорт из TMDB;
  2. `imdb_id` → каталог, иначе TMDB `/find` → импорт из TMDB;
  3. `kp_id` → каталог (сопоставление `kinopoisk`, в том числе от прошлых импортов);
  4. Wikidata по `kp_id` (см. ниже): пара TMDB из файла соответствия, иначе его IMDb (каталог, затем `/find`);
  5. поиск TMDB по `title_original` (если пусто — по `title_ru`) и году: `Film`/`Video` ищутся среди фильмов, `TvSeries`/`MiniSeries`/`TvShow` среди сериалов; принимается, только если ровно у одного результата нормализованное название равно искомому, а год отличается не больше чем на 1;
  6. иначе фильм склеивается с единственным фильмом каталога с тем же нормализованным названием и годом (как раньше), либо создаётся без пары TMDB (`unresolved`). Неоднозначные случаи создают отдельный фильм (`movies ambiguous`).

  Найденному фильму добавляются сопоставления `kinopoisk` и `imdb`; ID, уже занятый другим фильмом, не перепривязывается, а попадает в `conflicts`. Ответы TMDB шагов 2 и 4 кэшируются в таблице `tmdb_lookups`, поэтому повторный и прерванный импорт не повторяют запросы. `--no-tmdb` пропускает запрос `/find` и поиск (шаги 2 и 4); без `TMDB_API_KEY` команда работает так же, с предупреждением.
- **Сопоставление через Wikidata.** Соответствие `kp_id` → TMDB/IMDb берётся из Wikidata (свойства P2603, P4947, P4983, P345) и сокращает число `unresolved`:

  ```
  cinemate fetch-wikidata-kinopoisk [--out data/wikidata_kinopoisk.csv]
  cinemate import-ratings-csv --file data/ratings.csv [--wikidata data/wikidata_kinopoisk.csv]
  ```

  `fetch-wikidata-kinopoisk` делает SPARQL-запросы страницами и пишет CSV `kp_id,tmdb_type,tmdb_id,imdb_id` (повторный запуск перезаписывает файл). `kp_id` с несколькими разными парами TMDB и пары, общие для нескольких `kp_id`, отбрасываются; их число печатается в сводке. Если файл `data/wikidata_kinopoisk.csv` существует, `import-ratings-csv` использует его сам; без файла импорт работает как раньше. Шаг работает и с `--no-tmdb`, если фильм с такой парой уже есть в каталоге. Повторный импорт дозаполняет фильмы, привязанные к `kinopoisk` без пары TMDB: свободная пара присваивается фильму, а если пара уже принадлежит другому фильму, фильм из файла сливается с ним (остаётся владелец пары, оценки переносятся). В сводке — `by Wikidata` и `merged by Wikidata`.
- Пользователи хранятся как `is_synthetic=True`, только с идентификатором из файла, без имён; создаются при наличии хотя бы одной оценки (пользователи с менее чем 20 оценками остаются без оценок и не создаются). Сырые оценки 1–10 не хранятся, только `+1`/`-1`.
- Повторный запуск ничего не добавляет и не меняет; `Movie.popularity_score` пересчитывается.
- Постеры и описания есть у фильмов, для которых удалось установить пару TMDB; у `unresolved` их нет.

## Переменные окружения

| Переменная     | Назначение                                                        |
| -------------- | ----------------------------------------------------------------- |
| `TMDB_API_KEY` | ключ TMDB API для `enrich-movies` и поиска в API (`serve`)        |
| `DATABASE_URL` | URL БД для `import-movielens`, `import-ratings-csv`, `enrich-movies`, `metrics`, `serve` |

URL базы данных выбирается так: аргумент `--database-url` → переменная `DATABASE_URL` →
`sqlite:///cinemate.db`. Шаблон переменных — в `.env.example`; настоящий `.env` не
коммитьте (он в `.gitignore`). CLI сам `.env` не читает: экспортируйте переменные в
окружение.

## Запуск приложения локально

Путь от пустого репозитория до сайта на `localhost`. Нужны Python 3.12+ и Node.js.

1. **Python-часть** (см. «Установка» выше):

   ```
   python -m venv .venv && source .venv/bin/activate
   pip install -e ".[dev]"
   ```

2. **Данные.** Импорт MovieLens в SQLite (`cinemate.db` в текущем каталоге; MovieLens
   скачивается в `data/`):

   ```
   cinemate import-movielens --data-dir data
   ```

   Необязательно — постеры и описания из TMDB (нужен ключ):

   ```
   export TMDB_API_KEY=...
   cinemate enrich-movies --limit 200
   ```

3. **API:**

   ```
   cinemate serve --host 127.0.0.1 --port 8000
   ```

   При работе по HTTPS добавьте `--cookie-secure` (или `COOKIE_SECURE=1`), чтобы cookie сессии
   ставилась с флагом `Secure`.

   Проверка: <http://127.0.0.1:8000/api/health> и документация <http://127.0.0.1:8000/docs>.

4. **Фронтенд** (в другом терминале):

   ```
   cd frontend
   npm install
   cp .env.example .env.local   # API_INTERNAL_URL — адрес API; настройка CORS не нужна
   npm run dev
   ```

   Сайт: <http://localhost:3000>.

### Типичные проблемы

- **Пустая лента или онбординг без карточек** — не выполнен `cinemate import-movielens`, либо
  API запущен с другой базой (проверьте `--database-url` / `DATABASE_URL` в обоих командах).
- **Запросы отвечают 502 `API unavailable`** — фронтенд не достучался до API: запустите
  `cinemate serve` и проверьте `API_INTERNAL_URL`.
- **Cookie сессии не ставится, запросы отвечают 401** — оставьте `NEXT_PUBLIC_API_URL` пустым:
  браузер ходит на `/api/*` фронтенда, и cookie остаётся first-party. Если вы указали прямой адрес
  API, открывайте сайт на `localhost:3000`, держите API на `localhost:8000` (не `127.0.0.1`), а
  `CORS_ORIGINS` должен точно совпадать с адресом сайта.
- **Нет постеров и описаний** — не выполнен `cinemate enrich-movies` (нужен `TMDB_API_KEY`).

## Матрица оценок и замер рекомендаций

API держит в памяти матрицу оценок каждого пула (`MatrixStore`). Матрица строится
синхронно только при первом обращении к пулу, если он не успел собраться при старте: матрицы
всех пулов строятся в фоне при старте API, поэтому после перезапуска первые несколько секунд
рекомендации могут отвечать дольше. Новые оценки лишь помечают пул «устаревшим»:
следующий запрос не раньше чем через `MATRIX_REBUILD_SECONDS` (по умолчанию 300) после
прошлой сборки запускает пересборку в фоновом потоке, а пока она идёт, отдаётся старая
матрица; новая подменяется атомарно. Собственные оценки пользователя читаются из БД при
каждом запросе, поэтому влияют на его ленту сразу, а оценки других пользователей попадают в
соседей после ближайшей пересборки. Ошибка пересборки оставляет старую матрицу.

```
cinemate bench-recommendations [--database-url URL] [--pool world] [--requests 20] [--seed 0]
                               [--synthetic N]
```

Команда печатает время загрузки матрицы, её размер (пользователи, фильмы, ненулевые),
объём массивов матрицы в МБ и p50/p95 времени `get_recommendations` для случайных
пользователей пула. С `--synthetic N` пустая БД сначала заполняется примерно `N` случайных
оценок (для замеров на больших объёмах, например `--synthetic 5000000`).

## Профиль вкуса

Лента строится коллаборативной фильтрацией, затем кандидаты переупорядочиваются по вкусу
пользователя (`cinemate/recommender/taste.py`, только для стратегии `collaborative`).

- **Признаки фильма:** жанры (ID TMDB), тип (`movie`/`tv`), анимация и аниме (жанр 16 и
  оригинальный язык `ja`), десятилетие, язык оригинала. Они берутся из кэша `MatrixStore`
  (загружаются при сборке матрицы без ORM-объектов), там же доли `base_f` признаков среди лайков пула.
- **Профиль:** по признаку `f` из лайков `L_f` и дизлайков `D_f` пользователя (отметка «Не
  интересует» — дизлайк с весом 0,5): качество `q_f = (L_f − D_f) / (L_f + D_f + 2)`, интерес
  `i_f = ln((L_f + 1) / (E_f + 1))`, где `E_f` — число лайков пользователя × `base_f`, вклад
  `q_f + w_i · i_f`. Оценка фильма — среднее по группам признаков, внутри группы — среднее по
  признакам фильма; без признаков — 0.
- **Переранжирование:** CF отбирает до 200 кандидатов, порядок — `z(cf) + γ · z(taste)`
  (стандартизация внутри списка кандидатов). Затем в любых 10 позициях подряд остаётся не
  больше 4 фильмов с одинаковым главным (самым редким среди лайков пула) жанром и не больше 2
  из одной коллекции; лишние сдвигаются ниже, не выбрасываясь.
- **Настройка:** `REC_TASTE_WEIGHT` (`γ`, по умолчанию `0.5`) и `REC_TASTE_INTEREST_WEIGHT`
  (`w_i`, `0.5`). `REC_TASTE_WEIGHT=0` выключает переранжирование и ограничения разнообразия:
  порядок остаётся прежним, `because_taste` не отдаётся.
- **Объяснение:** если главный положительный вклад в оценку фильма даёт жанр или
  анимация/аниме, которые пользователь лайкнул не меньше 3 раз (вклад выше 0,5), в
  `GET /api/recommendations` у элемента есть `because_taste: {kind, id, name}` (`name` на языке
  запроса), и лента показывает «Вы часто лайкаете фэнтези». Без уверенного признака поля нет
  (`null`).

Офлайн-оценка: `cinemate evaluate` на MovieLens добавляет строку `cf+taste` (жанры и год из
`movies.csv`, `γ` и `w_i` из `REC_TASTE_WEIGHT` / `REC_TASTE_INTEREST_WEIGHT`), а `cinemate tune`
перебирает `γ` и `w_i` для лучших параметров CF:

```
cinemate evaluate --seeds 0,1,2
cinemate evaluate --seeds 0,1,2 --new-user-ratings 15
cinemate tune --seeds 0,1,2 --taste-weight 0,0.25,0.5,1 --taste-interest 0,0.5
cinemate tune --seeds 0,1,2 --new-user-ratings 15
```

Для `--source csv` признаков нет, строки `cf+taste` не будет.

## A/B-проверка вариантов рекомендаций

Профиль вкуса и правила для дизлайкнутых категорий можно сравнить на живых пользователях.

- **Включить:** `REC_AB_VARIANTS=control,taste`. Вариант — именованный набор настроек:
  `control` — `REC_TASTE_WEIGHT=0`, штраф за сходство с дизлайкнутыми и скрытие категорий
  выключены; `taste` — текущие настройки. Пустое значение: A/B выключен, все получают текущие
  настройки, в событиях `variant` пуст.
- **Назначение:** детерминированное, `sha256(user_id)` по модулю числа вариантов. Пользователь
  всегда видит один вариант. Вариант нигде не хранится, а вычисляется, поэтому **смена списка
  `REC_AB_VARIANTS` переназначает всех пользователей**: данные до и после смены не сравнивайте.
- **События:** `GET /api/recommendations` пишет вариант в `impression` (колонка
  `events.variant`, миграция 0013, нужен `cinemate migrate`). Реакции с `session_id` получают
  вариант из `impression` той же сессии.
- **Результат:** `cinemate metrics --by-variant` (учитывает `--since`) печатает по каждому
  варианту: число пользователей и сессий, `good_session_rate`, отношение лайков к дизлайкам
  в реакциях ленты, долю «Не интересует» среди реакций и `retention_7d` пользователей варианта.
  Сессии без варианта (до включения A/B) собраны под именем `none`.
- **Сколько ждать:** при малом числе пользователей различия шумные. Сравнивайте, когда в каждом
  варианте не меньше 100 сессий; `retention_7d` считается только по пользователям, чей первый
  шаг старше 7 дней, поэтому ему нужно больше времени. Значимость не проверяется: смотрите на
  размер разницы и на то, что метрики идут в одну сторону (лучше `good_session_rate` и
  отношение лайков к дизлайкам, ниже доля «Не интересует»).

## Скрытые категории

Если пользователь дизлайкнул категорию целиком, её фильмы не должны быть вверху ленты, даже когда
они понравились соседям (`cinemate/recommender/categories.py`, `cinemate/services/categories.py`).

- **Категории:** коллекция (франшиза); «узнаваемая» студия — не больше `REC_HIDE_STUDIO_MAX_MOVIES`
  (150) оценённых фильмов в пуле, поэтому Marvel Studios, Pixar или A24 подходят, а Warner Bros. и
  Universal нет; жанр (в том числе анимация); аниме (анимация и `original_language = ja`).
- **Срабатывание:** в категории ноль лайков и не меньше дизлайков, чем порог: 3 для коллекции,
  студии и аниме (`REC_HIDE_DISLIKES_COLLECTION` / `_STUDIO` / `_ANIME`), 5 для жанра
  (`REC_HIDE_DISLIKES_GENRE`). Отметки «Не интересует» не считаются. Один лайк в категории отменяет
  правило.
- **Действие:** фильмы сработавших категорий ставятся сразу после 20-й позиции с сохранением
  порядка между собой, совсем не удаляются. Это делается после переранжирования по вкусу; ради
  этого кандидатов берётся до 200.
- **Плашка в ленте:** «Опустили ниже: Marvel Studios — вы дизлайкнули 5 из 5 · Анимация — вы
  дизлайкнули 6 из 6» и у каждой категории кнопка «Показывать».
- **Отмена:** таблица `user_category_prefs (user_id, kind, key, mode, updated_at)`, `mode` — только
  `show`, уникальность по (`user_id`, `kind`, `key`). Отмена действует, пока пользователь сам её не
  снимет; новые дизлайки её не отменяют.
  - `GET /api/category-prefs` — категории, опущенные правилом сейчас (`show: false`), и отменённые
    пользователем (`show: true`) с числами `disliked` из `rated`; названия на языке запроса
    (жанры из справочника, аниме) или как в TMDB (коллекции, студии).
  - `POST /api/category-prefs {kind, key, show}`: `kind` — `collection`, `studio`, `genre` или
    `anime` (`key` аниме — `anime`); `true` — показывать несмотря на оценки, `false` — вернуть
    автоматическое правило.
  - В профиле раздел «Скрытые категории» с переключателем «Показывать» / «Скрывать».

### Сходство с дизлайкнутыми фильмами

У пользователей с не меньше чем `REC_DISLIKE_ITEM_MIN_RATINGS` (50) оценок кандидаты штрафуются за
сходство с дизлайкнутыми фильмами по оценкам других людей: для кандидата берётся максимальная
косинусная близость его столбца матрицы к столбцам дизлайкнутых фильмов, итоговый порядок —
`z(cf) + γ · z(taste) − ε · z(близость)`, `ε = REC_DISLIKE_ITEM_WEIGHT` (0,5; `0` выключает).
Считается только для кандидатов, матрица фильм × фильм не строится. У новых пользователей штраф
вредит точности, поэтому до порога он не включается.

### Офлайн-оценка

`cinemate evaluate` на MovieLens добавляет строку `cf+taste+rule`: те же кандидаты, что у
`cf+taste`, плюс правило скрытия и штраф (настройки из переменных выше). У MovieLens есть только
жанры, поэтому из категорий срабатывает лишь жанр:

```
cinemate evaluate --seeds 0,1,2
cinemate evaluate --seeds 0,1,2 --new-user-ratings 15
REC_DISLIKE_ITEM_MIN_RATINGS=15 cinemate evaluate --seeds 0,1,2 --new-user-ratings 15
```

## Пулы пользователей

Пользователи делятся на два пула, `users.pool`: `ru` и `world`. Соседи, «популярное» (запасная
стратегия) и карточки онбординга считаются только по оценкам пользователей своего пула.

- **Назначение.** `POST /api/session` при создании пользователя читает `Accept-Language`: если
  язык с наибольшим приоритетом — русский (`ru`, `ru-RU`), пул `ru`, иначе (в том числе без
  заголовка) `world`. Пул сохраняется один раз и дальше не меняется; он возвращается в ответе
  `POST /api/session` (поле `pool`).
- **Данные пула `ru`** — набор оценок владельца: `cinemate import-ratings-csv` создаёт
  пользователей с `pool='ru'`.
- **Данные пула `world`** — MovieLens: `cinemate import-movielens` создаёт пользователей с
  `pool='world'`. Оценки живых пользователей пополняют матрицу только их пула.
- **Миграция `0005`** добавляет колонку: существующие пользователи с `external_ratings_id`
  получают `ru`, остальные — `world`. Примените её командой `cinemate migrate`.
- **Через сайт.** Прокси Next.js пересылает в API заголовок `Accept-Language`, поэтому пул
  определяется языком браузера. Пользователи, созданные до этого исправления, остались в `world`:
  чтобы получить пул `ru`, удалите cookie `cinemate_session` для `localhost:3000` (или откройте
  окно инкогнито) или нажмите «Начать заново» в профиле.
- **Начать заново.** `POST /api/session/reset` создаёт нового анонимного пользователя (пул по
  cookie `cinemate_lang`, затем `Accept-Language`) и ставит новую cookie `cinemate_session`.
  Старый пользователь, его оценки и события остаются в БД. `GET /api/me` возвращает
  `{user_id, pool, rated_count}`; профиль показывает кнопку «Начать заново» и предупреждает только о потере оценок.
- **Как проверить пул.** В интерфейсе пул не показывается. Откройте
  `http://localhost:3000/api/me` в браузере: поле `pool` — пул текущего пользователя. Чтобы
  проверить оба пула, переключите язык RU/EN в навигации, нажмите в профиле «Начать заново» и
  снова откройте `/api/me`: новый профиль попадёт в пул `ru` (RU) или `world` (EN).

## Как добавить язык

1. Фронтенд: запись в `LANGUAGES` в `frontend/src/lib/locale.ts` (`code`, `label`, `name`,
   `flag`). Тип `Lang` и выпадающий список в навигации берут значения оттуда.
2. Переводы: словарь нового языка в `frontend/src/lib/i18n.ts` (и формы множественного числа
   в `PLURALS`). Без них `npm run typecheck` падает.
3. API: запись в `LANGUAGES` в `cinemate/services/users.py` с языком поиска TMDB
   (`tmdb_language`, например `de-DE`) и пулом пользователей (`pool`: `ru` или `world`).

Cookie `cinemate_lang` принимает любой код из списка. Без cookie берётся основной язык
браузера, если он есть в списке, иначе `en` (на фронтенде и в API одинаково).

## Миграции базы

Схема БД управляется Alembic (`alembic.ini`, каталог `migrations/`). URL базы берётся так же, как
у остальных команд: `--database-url`, затем `DATABASE_URL`, затем `sqlite:///cinemate.db`.

- Применить миграции: `cinemate migrate` (то же, что `alembic upgrade head`). Повторный запуск
  ничего не меняет.
- Локальная база, созданная раньше без миграций (через `create_all`): один раз выполните
  `cinemate migrate --stamp-existing` — команда проставит последнюю ревизию, не трогая таблицы и
  данные; дальше работает обычный `cinemate migrate`.
- Создать ревизию после изменения `cinemate/db/models.py`:
  `alembic revision --autogenerate -m "описание"`, проверьте файл в `migrations/versions/` и
  примените его через `cinemate migrate`.
- `cinemate serve` на in-memory SQLite создаёт схему сам; пустой файл SQLite (в том числе
  `cinemate.db` по умолчанию) инициализируется миграциями автоматически. На любой другой базе
  (например, PostgreSQL) сервер не стартует, пока схема не на актуальной ревизии: выполните
  `cinemate migrate`.

## Каталог фильмов

- `movies.id` — единственный ключ внутри системы: API, оценки и матрица работают только с ним.
- Главный внешний идентификатор — пара (`tmdb_type`, `tmdb_id`), где `tmdb_type` — `movie` или
  `tv` (у TMDB это разные пространства ID). Пара уникальна; у фильма, которого нет в TMDB, она
  пустая.
- Остальные внешние ID лежат в таблице `movie_external_ids` (`source`, `external_id`,
  `movie_id`): источники `movielens`, `imdb`, `kinopoisk`, `ratings_csv`. Один фильм может иметь
  несколько ID одного источника (дубли MovieLens), один ID принадлежит одному фильму.
- Поиск и привязка — `cinemate/db/catalog.py` (`find_movie`, `link`, `merge_movies`). Старые
  столбцы `external_*_id` и `imdb_id` пока остаются, но код читает ID из таблицы сопоставления.
- Миграция `0004` сливает фильмы с одинаковой парой TMDB: остаётся строка с минимальным `id`,
  оценки, отметки и события переносятся на неё (при оценках одного пользователя на оба дубля
  остаётся более поздняя; у отметок нет времени, берётся запись с большим `id`).

### Поиск любого фильма или сериала TMDB

Страница `/search` ищет по всему TMDB (более 1,4 млн названий), а не только по фильмам
MovieLens. Нужен `TMDB_API_KEY` в окружении `cinemate serve` (в `docker compose` он передаётся
сервису `api`); ключ остаётся на сервере и в браузер не попадает.

- `GET /api/search?q=&page=1` — `q` от 2 до 100 символов; язык запроса к TMDB `ru-RU`, если
  основной язык `Accept-Language` русский, иначе `en-US`. В ответе `movie_id` (наш ID, если
  фильм уже в каталоге) и `user_value` (оценка пользователя). Ответы TMDB кэшируются в памяти
  процесса (до 1000 запросов, 24 часа). Без ключа — 503, ошибка TMDB — 502.
- **Источник поиска** задаёт `SEARCH_SOURCE` (или параметр `search_source` у `create_app`):
  - `tmdb` — всегда живой поиск в TMDB (как выше); без ключа 503.
  - `local` — только своя база (`title`, `original_title`, `title_ru` фильмов с парой TMDB), TMDB не
    нужен.
  - `auto` (по умолчанию) — своя база, если в каталоге не меньше 100 000 записей с парой TMDB
    (например, после `cinemate sync-catalog --min-popularity 1`); размер проверяется при старте и
    раз в час, а не на каждый поиск. Пока записей меньше, ищет в TMDB. Если своя база ничего не
    нашла на первой странице и ключ задан, ищет в TMDB. Без ключа `auto` и `local` работают.
  - Поиск по своей базе нормализует запрос (регистр, `ё`→`е`, знаки препинания). Порядок: точное
    совпадение названия, начало названия, остальное; внутри группы по `tmdb_popularity` по
    убыванию. Год в запросе («Дюна 2021») не разбирается. На PostgreSQL миграция `0010` включает
    `pg_trgm` и строит GIN-индексы по нормализованным (регистр, `ё`, знаки препинания) трём названиям; на
    SQLite индексов нет, поиск по подстроке.
- `POST /api/movies/resolve` с `{tmdb_type, tmdb_id}` создаёт фильм в каталоге (если его ещё нет)
  и возвращает карточку с нашим `id`; оценка ставится через `POST /api/ratings`.
- К TMDB не больше 20 запросов в секунду на процесс; на 429 выдерживается пауза по `Retry-After`
  и запрос повторяется один раз.

### Своя копия каталога TMDB

`cinemate sync-catalog` загружает каталог TMDB в свою базу по ежедневным выгрузкам ID
(`movie_ids_MM_DD_YYYY.json.gz`, `tv_series_ids_MM_DD_YYYY.json.gz` с `files.tmdb.org`; ключ для
выгрузок не нужен, для деталей фильмов нужен `TMDB_API_KEY`). Новые пары (`tmdb_type`, `tmdb_id`)
берутся по убыванию популярности: если загрузку прервать, самое популярное уже в базе.

```
cinemate sync-catalog --min-popularity 1                 # рекомендуемый старт
cinemate sync-catalog --type movie --limit 5000          # порция за запуск
docker compose run --rm app sync-catalog --min-popularity 1
```

Параметры: `--type {movie,tv,all}`, `--min-popularity X`, `--include-video` (без него записи
`video: true` пропускаются; `adult: true` пропускаются всегда), `--limit N`, `--date YYYY-MM-DD`
(по умолчанию сегодня по UTC; если выгрузки ещё нет, берётся вчерашняя), `--export-dir`
(по умолчанию `data/tmdb_exports`, уже скачанный файл повторно не качается), `--workers N` и
`--rps X` (см. ниже «Скорость загрузки из TMDB»; они же у `--changes` и `enrich-movies`).

- **Возобновляемость.** Коммит каждые 500 записей; повторный запуск пропускает пары, которые уже
  есть в базе, и дублей не создаёт. Раз в 1000 записей печатается прогресс и оценка времени.
  У уже загруженных записей `movies.tmdb_popularity` обновляется из выгрузки без запросов к TMDB.
- **Время** (выгрузки за 27.10.2026, 20 запросов в секунду): весь каталог (около 1,5 млн записей)
  примерно 21 час; с `--min-popularity 1` около 620 тысяч записей, примерно 9 часов.
  Без параллельности и постоянных соединений (версии до `--workers`) выходило около 4,5 записи в
  секунду, то есть около 30 часов на 488 тысяч записей.
- **Место в PostgreSQL:** порядка 2–3 ГБ на весь каталог.
- Загруженные записи без оценок не попадают в онбординг и запасную стратегию: они строятся по
  матрице оценок.
- **Условия TMDB:** только некоммерческое использование, данные не старше 6 месяцев — обновляйте
  их через `cinemate enrich-movies` (`tmdb_fetched_at`).

#### Скорость загрузки из TMDB

`sync-catalog` (обе формы) и `enrich-movies` запрашивают детали параллельно и держат постоянные
HTTPS-соединения (по одному на поток), поэтому скорость упирается в `--rps`, а не в задержку
сети.

- `--workers N` — число потоков, 1–16, по умолчанию 8. `--workers 1` — по одной записи, как раньше.
- `--rps X` — общий предел запросов в секунду на все потоки, до 35, по умолчанию 20. Верхняя
  граница TMDB по [документации](https://developer.themoviedb.org/docs/rate-limiting) около 40.
  API (`serve`) остаётся на 20.
- **Ожидаемая скорость:** при 8 потоках и `--rps 20` около 20 записей/с (488 тысяч записей примерно
  за 7 часов); при `--rps 35` около 4 часов. В строке прогресса печатаются `workers` и `rps`.
- **429.** Ответ «слишком много запросов» в любом потоке ставит паузу всем потокам на
  `Retry-After`, затем запрос повторяется. После 5 таких ответов подряд команда останавливается
  с сообщением; прогресс сохранён, запустите её позже или уменьшите `--rps` и `--workers`.
- **Прерывание.** Ctrl+C: новые запросы не отправляются, уже полученные записываются, всё
  коммитится. Повторный запуск продолжает, загруженные пары пропускаются.
- **Перейти на новую версию посреди загрузки:** Ctrl+C, затем
  `docker compose --profile tools build app` и та же команда с `--workers`, например
  `docker compose run --rm app sync-catalog --min-popularity 1 --workers 8 --rps 20`;
  загруженное не повторяется.

#### Ежедневная синхронизация (`--changes`)

После первичной загрузки каталог держится свежим через `/movie/changes` и `/tv/changes` TMDB:
за сутки приходит несколько тысяч изменённых записей (около 800 новых в день), это минуты работы.

```
cinemate sync-catalog --changes
docker compose run --rm app sync-catalog --changes
```

Запускайте раз в сутки. На Windows: Планировщик заданий, действие `docker compose run --rm app
sync-catalog --changes` (рабочая папка — каталог проекта), триггер «ежедневно».

- Параметры: `--type {movie,tv,all}`, `--since YYYY-MM-DD`, `--limit N`, `--min-popularity X`,
  `--workers N`, `--rps X`.
- **Период:** от `catalog_sync.changes_synced_until` (по типу), иначе `--since`, иначе 1 день
  назад; до текущего момента. Окна длиннее 14 дней режутся на части. Если период длиннее 90 дней,
  команда советует полную загрузку по выгрузке (`sync-catalog` без `--changes`) и завершается с
  кодом 2.
- Пара уже есть в базе — запись обновляется теми же правилами, что в `enrich-movies` (пустое
  значение TMDB не стирает сохранённое, `tmdb_fetched_at` обновляется); пары нет — создаётся
  (если задан `--min-popularity`, записи с меньшей популярностью не создаются, существующие
  обновляются); 404 — пропуск со счётчиком.
- `changes_synced_until` сдвигается только после обработки всего периода типа. Прогресс
  коммитится каждые 500 записей; после прерывания (или остановки по `--limit`) повторный запуск
  берёт тот же период и пропускает записи, уже загруженные с начала его первого дня, поэтому
  повторный запуск в тот же день почти ничего не запрашивает.
- `enrich-movies` раз в неделю по-прежнему нужен: он обновляет записи, которых изменения не
  коснулись, чтобы данные не были старше срока TMDB (6 месяцев).

## Признаки фильмов

Для персонализации у фильмов с парой TMDB хранятся (всё приходит в базовом ответе деталей,
дополнительных запросов нет):

- **жанры** — единый словарь `genres` (ID жанров TMDB, `name_en`, `name_ru`), связь
  `movie_genres`. Сериальные «составные» жанры раскладываются на фильмовые (10759 → 28 + 12,
  10765 → 878 + 14, 10768 → 10752); Kids, News, Reality, Soap, Talk остаются своими ID. API
  отдаёт названия на языке запроса (`cinemate_lang`, затем `Accept-Language`);
- **франшиза** — `collections`, `movies.collection_id`;
- **студии** — `companies` (с `logo_path`), связь `movie_companies`;
- `movies.countries` (ISO 3166-1), `movies.original_language` (ISO 639-1),
  `movies.tmdb_vote_average` и `movies.tmdb_vote_count`.

Жанры записей с парой TMDB перезаписываются жанрами TMDB при добавлении из поиска,
`sync-catalog`, `sync-changes` и `enrich-movies`. У фильмов без пары (MovieLens, CSV Кинопоиска)
остаются жанры, переведённые в тот же словарь по таблицам из `cinemate/genres.py`; «IMAX»,
«(no genres listed)» и не имеющие соответствия жанры («биография», «спорт», «короткометражка»)
отбрасываются. Столбец `movies.genres` остаётся, но не используется.

Загрузка каталога (`sync-catalog`), запущенная до миграции `0011`, признаков не пишет. Их
дозаполняет команда (сначала фильмы с оценками в любом пуле, затем остальные; для ~90 тысяч
фильмов с оценками порядка 1,5 часа):

```
cinemate enrich-movies --missing-features [--limit N]
```

Признаки считаются отсутствующими, пока `movies.tmdb_vote_count` пуст.

## Данные карточки фильма

Для страницы фильма из TMDB хранятся (таблицы `people`, `movie_credits`, `keywords`,
`movie_keywords` и поля `movies`):

- **люди** (`movie_credits`, роль `role`): первые 15 актёров по `order` (`cast`, с именем
  персонажа), все режиссёры (`director`), до 3 сценаристов (`writer`: Writer, Screenplay), до 3
  продюсеров (`producer`: Producer), композитор (`composer`: Original Music Composer). У сериалов
  создатели (`creator`) берутся из `created_by`, состав из `aggregate_credits`, режиссёры сериалов
  не хранятся (их сотни у одного сериала). Имена как отдаёт TMDB, обычно латиницей;
- **ключевые слова** (`keywords`) только на английском;
- **возрастной рейтинг** `movies.certification` и страна `movies.certification_country`: страна
  `RU` для русского интерфейса, иначе `US`; если у выбранной страны рейтинга нет, берётся `US`;
- `budget`, `revenue`, `tagline`, у сериалов `number_of_seasons` и `number_of_episodes` (эти поля
  есть в обычном ответе, их пишет и обычный `enrich-movies`).

Расширенные данные приходят в том же запросе деталей (`append_to_response`), но ответ заметно
больше, поэтому `sync-catalog` их не запрашивает. Время получения: `movies.details_fetched_at`.
Состав и ключевые слова при повторном получении заменяются целиком. Запрашиваются:

- **при открытии карточки** (`GET /api/movies/{id}`): если у фильма есть пара TMDB, а данных нет
  или они старше 30 дней, один синхронный запрос. Без ключа TMDB или при ошибке TMDB карточка
  отдаётся с тем, что есть;
- **`cinemate enrich-movies --extended`**: фильмы с оценками в любом пуле, у которых данных нет
  или они устарели (`--stale-days`); нельзя сочетать с `--missing-features` и `--refresh-titles`.
  Для ~90 тысяч фильмов с оценками это порядка 1,5 часа;
- обычный `enrich-movies` обновляет расширенные данные только у тех, у кого они уже есть и
  устарели.

```
export TMDB_API_KEY=...
cinemate enrich-movies --extended --workers 8
```

## Docker

Весь продукт (PostgreSQL, API и фронтенд) поднимается одной командой. Драйвер PostgreSQL ставится
extra `postgres`; образ API собирается с ним.

1. Создайте `.env` и задайте `POSTGRES_PASSWORD` (шаблон — `.env.example`; значений по умолчанию
   в файлах нет):

   ```
   cp .env.example .env
   ```

2. Примените миграции базы (до первого `up`: API не стартует на базе без актуальной схемы;
   команда сама поднимет `db`):

   ```
   docker compose run --rm app migrate
   ```

3. Соберите и запустите сервисы (порядок задан healthcheck'ами: `db` → `api` → `frontend`):

   ```
   docker compose up --build -d
   ```

4. Выполните первичный импорт данных (один раз):

   ```
   docker compose run --rm app import-movielens --data-dir data
   docker compose run --rm app enrich-movies    # по желанию, нужен TMDB_API_KEY в .env
   ```

5. Откройте сайт: <http://localhost:3000>. API наружу не публикуется, фронтенд проксирует `/api`.

Другие разовые команды: `docker compose run --rm app metrics`. Сервис `app` относится к профилю
`tools`, поэтому `docker compose up` его не запускает.

Остановка: `docker compose down`; с удалением данных базы (том `pgdata`): `docker compose down -v`.

Данные MovieLens монтируются томом `./data`. Пароль подставляется в URL без кодирования —
используйте только URL-безопасные символы (без `@ / : #`). Контейнер работает от пользователя
uid 10001: каталог `./data` должен быть ему доступен на запись.
