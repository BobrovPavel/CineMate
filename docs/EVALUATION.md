- Лучшая комбинация: K=40, lambda=10, min_overlap=3.

### Определение mean popularity

В `evaluate` (`cinemate/evaluation/runner.py`) популярность фильма — это доля пользователей обучающей выборки, лайкнувших фильм (число лайков в train, делённое на число пользователей train). Для каждого пользователя берётся среднее по его рекомендованным фильмам (`mean_popularity` в `cinemate/evaluation/metrics.py`, неизвестный фильм считается за 0), затем значение усредняется по оценённым пользователям.

- Сильные baseline: `popular_likes` (топ по числу лайков) даёт precision@10 = 0.1341, recall@10 = 0.0924, coverage = 0.0060; `popular_share_50` — 0.0497; `popular_share_20` — 0.0157, то есть практически совпадает с прежним слабым `popular` (0.0152). Честное сравнение — с `popular_likes`.

- Вывод: значения по умолчанию из настроек (K=40, lambda=40, min_overlap=3, pop_penalty=1.0) совпадают с точкой «precision почти максимальный при нормальном coverage».
- Для пользователей с 5–10 оценками см. прогон 4: вывод про превосходство CF к ним не относится.

### Ограничения оценки

- Один seed разбиения и 604 пользователя; разница порядка 0.003 в precision находится в пределах шума, доверительные интервалы не считались.
- Пользователи ml-latest-small имеют не меньше 20 оценок, а пользователь сайта после онбординга оценит заметно меньше (порог запасной стратегии — 5 оценок, см. docs/VISION.md; основной сценарий — около 10 оценок), поэтому результаты нельзя переносить на «холодный старт» без отдельной проверки.

### Наблюдения по фактам

- При 5 оценках у новых пользователей `collaborative` (precision@10 = 0.0213, hit_rate@10 = 0.1833) заметно хуже `popular_likes` (0.1297 и 0.5667): precision ниже в ~6.1 раза, hit rate ниже на ~38 п.п. Он близок к слабым baseline (`popular`: 0.0253 и 0.1967, `popular_share_20`: 0.0283 и 0.2133).
- Строка `product` (CF плюс запасная стратегия, как на сайте) при 5 оценках почти совпадает с `collaborative` (precision@10 = 0.0237, hit_rate@10 = 0.2000).
- При 10 оценках CF сильно подтягивается: precision@10 растёт с 0.0213 до 0.0939 (в ~4.4 раза), hit_rate@10 — с 0.1833 до 0.5253, тогда как `popular_likes` почти не меняется (0.1297 → 0.1350 и 0.5667 → 0.5724).
- При 10 оценках CF по precision@10 ниже `popular_likes` (0.0939 против 0.1350, −30%), по recall@10 выше (0.0953 против 0.0862, +11%), по hit_rate@10 ниже на ~4.7 п.п. (0.5253 против 0.5724). Coverage — 0.1294 против 0.0076 (в ~17 раз), mean popularity — 0.0610 против 0.1573.
- `popular_share_50` при 10 оценках близок к CF по precision (0.0980 против 0.0939) и ниже по recall (0.0478 против 0.0953).
- Вывод по фактам: при 5–10 оценках user-based CF с параметрами по умолчанию не превосходит «популярное по числу лайков», а `product` на этих объёмах почти повторяет CF. Точка, в которой CF обгоняет `popular_likes`, лежит выше 10 оценок и в этом прогоне не определена.
- Параметры для холодного старта подобраны в прогоне 5: с `min_overlap=1` CF не хуже `popular_likes` (на лучших строках `tune`, один seed, оценка оптимистична; при `pop_penalty=1` и 5 оценках — ниже).

### Ограничения оценки

- Один seed и около 300 пользователей; для hit rate стандартная ошибка порядка 0.03: разница 4.7 п.п. при 10 оценках в пределах шума, разница при 5 оценках — нет.
- «Новые» пользователи — случайная половина тех, у кого не меньше N оценок, годных для бинаризации. Их N оценок выбраны случайно среди этих оценок, а не из карточек онбординга (известные фильмы пересекаются с большим числом пользователей, поэтому оценка CF, вероятно, занижена).
- Параметры CF (K=40, lambda=40, min_overlap=3, pop_penalty=1) подобраны на пользователях с богатой историей, для холодного старта не подбирались.

### Что на сайте

- Запасная стратегия (`cinemate/recommender/fallback.py`) ранжирует фильмы по доле лайков при минимуме 5 оценок (как слабый baseline `popular`); из верхнего пула (в 3 раза больше выдачи) фильмы выбираются случайно.
- Порог перехода на CF — 5 оценок (`MIN_USER_RATINGS` в `cinemate/recommender/strategy.py`); запасная стратегия также включается, если CF ничего не вернул.

### Ограничения оценки

- Один seed разбиения, строки выбраны как лучшие из набора на одних данных, поэтому преимущество CF над `popular_likes` при 5 и 10 оценках оптимистично (стандартная ошибка precision@10 порядка 0.008, hit rate — около 0.03).
- «Новые» пользователи выбраны случайно из своих оценок, а не из карточек онбординга (`--new-user-pick onboarding`, #102).
- В оценке исключается всё, что пользователь когда-либо оценил, а на сайте исключается только то, что он отметил, поэтому абсолютные значения precision и hit rate для «популярного» оптимистичны (сравнение CF и baseline внутри одной таблицы корректно).
- K=40 в сравнении с K=60 относится к другим сеткам прогонов, сравнение приблизительное.

### Ограничения оценки

- Жанры фильмов в `evaluate` неизвестны, поэтому ограничение по жанру при выборе карточек не действует.
- «Новые» пользователи — половина тех, у кого нет менее N годных оценок среди фильмов списка онбординга, поэтому набор пользователей и значения `popular_likes` меняются с N (precision@10 `popular_likes`: 0.1360, 0.1429, 0.1606 при 3, 5 и 10 оценках); сравнивать абсолютные значения между разными N нельзя.

- В оценке исключается всё, что пользователь когда-либо оценил, а на сайте только отмеченное (завышает все методы, больше всего `popular_likes`).
- Стандартное отклонение — выборочное по 5 разбиениям.
